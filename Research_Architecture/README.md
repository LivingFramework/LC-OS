# Research Architecture

**Purpose:** Navigation infrastructure for the LC-OS research corpus.
Seven documents that make the corpus coherent, navigable, and future-proof.

---

## Documents in This Folder

| File | Purpose | Start here if... |
|------|---------|-----------------|
| [RESEARCH_INDEX.md](RESEARCH_INDEX.md) | Complete map of all 9 corpus documents (Papers 1–8 + Mahdi Ledger) | You want to understand what each paper covers |
| [RESEARCH_EVOLUTION_MAP.md](RESEARCH_EVOLUTION_MAP.md) | How concepts were born, evolved, merged across papers | You want to trace where an idea came from |
| [TERM_REGISTRY.md](TERM_REGISTRY.md) | Definitions and status of all key terms | You need to use a term precisely |
| [UNIFIED_SYNTHESIS.md](UNIFIED_SYNTHESIS.md) | The entire corpus in one readable document | You're new to the corpus |
| [RESEARCH_LAYER_SEPARATION.md](RESEARCH_LAYER_SEPARATION.md) | Six-layer organisation of the corpus | You need to know which layer a concept belongs to |
| [OPERATIONALIZATION_AUDIT.md](OPERATIONALIZATION_AUDIT.md) | Classification of templates by automation potential | You're thinking about building tools |
| [FUTURE_RESEARCH_PROTOCOL.md](FUTURE_RESEARCH_PROTOCOL.md) | How new papers enter the corpus going forward | You're planning a new paper |

---

## Recommended Reading Order

**New to the corpus:** UNIFIED_SYNTHESIS → RESEARCH_INDEX → TERM_REGISTRY

**Planning new research:** RESEARCH_EVOLUTION_MAP → TERM_REGISTRY → FUTURE_RESEARCH_PROTOCOL

**Building operational tools:** RESEARCH_LAYER_SEPARATION → OPERATIONALIZATION_AUDIT

**Deep dive on a specific concept:** TERM_REGISTRY (find the term) → RESEARCH_INDEX (find the paper) → RESEARCH_EVOLUTION_MAP (trace the lineage)

---

## What This Is Not

This folder is **navigation infrastructure**, not additional research.
None of these documents introduce new theoretical claims. They organise existing claims.

New research → submit as a paper following FUTURE_RESEARCH_PROTOCOL  
New operational tools → add to LC-OS-Project repo  
Updates to this folder → treat as maintenance, not publication
